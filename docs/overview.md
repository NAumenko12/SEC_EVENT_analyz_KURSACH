# Обзор Security Event Analyzer

Security Event Analyzer — учебная mini-SIEM с десктопным интерфейсом. Пользователь
загружает журнал безопасности или сетевой дамп, система разбирает данные,
приводит события к единому виду, ищет признаки подозрительной активности и
формирует понятный отчёт с уровнем риска и рекомендациями.

Проект не пытается заменить промышленную SIEM. Его задача — показать полный
путь события: от исходной строки журнала до результата анализа.

## Как работает система

Пользователь регистрируется или входит в десктопном приложении, собранном на React и Tauri.
React отвечает за экраны и элементы управления, а Tauri упаковывает интерфейс в
обычное приложение для компьютера.

Десктопный клиент обращается по HTTP к C++ API на Drogon. Поэтому в проекте
остаются запросы `GET`, `POST` и другие методы REST API: они связывают клиент и
серверную часть, а не зависят от того, открыт интерфейс в браузере или в
отдельном окне. На первом этапе API будет запущен на том же компьютере, а позднее
его можно будет без переделки клиента перенести на сервер.

API проверяет загруженный файл, сохраняет информацию о нём и создаёт задачу в
PostgreSQL. Каждая загрузка принадлежит вошедшему пользователю, поэтому другой
пользователь не может получить её состояние по идентификатору. После этого API
отправляет в Kafka небольшое сообщение с
идентификатором задачи. Сам файл через Kafka не передаётся.

Worker получает сообщение из Kafka, находит задачу и файл, выполняет парсинг и
нормализацию, применяет правила обнаружения и записывает в PostgreSQL события,
findings и итоговый отчёт. Благодаря очереди длительный анализ не блокирует
HTTP-запрос пользователя.

Для локальной разработки Kafka работает одним узлом в режиме KRaft. API является
producer, worker — consumer из группы `security-analyzer-workers`, а задания
передаются через topic `analysis.jobs`.

## Компоненты

- `backend` — REST API на C++ и Drogon;
- `worker` — фоновый C++-обработчик файлов;
- `shared` — общие C++-модели;
- `frontend` — десктопный клиент на React и Tauri;
- `database` — реляционная схема PostgreSQL;
- `docs` — архитектура и проектная документация.

## Безопасность базы данных

Файл `database/schema.sql` не выполняется автоматически при запуске контейнера.
Схема применяется только явной командой, поэтому перезапуск сервисов не может
неожиданно изменить структуру базы.

PostgreSQL из `compose.yaml` публикуется только на loopback-интерфейсе
`127.0.0.1` и недоступен другим компьютерам сети. Значения в `compose.yaml`
предназначены только для локальной разработки. Перед развёртыванием на сервере
логины и пароли необходимо передать через переменные окружения.

## Запуск локальной инфраструктуры

Запустите PostgreSQL и Kafka:

```bash
docker-compose up -d postgres kafka
```

Когда PostgreSQL перейдёт в состояние `healthy`, примените реляционную схему:

```bash
docker-compose exec -T postgres sh -c \
  'psql -v ON_ERROR_STOP=1 -U "$POSTGRES_USER" -d "$POSTGRES_DB"' \
  < database/schema.sql
```

Создайте topic, через который API будет передавать worker задачи анализа:

```bash
docker-compose exec kafka \
  /opt/kafka/bin/kafka-topics.sh \
  --bootstrap-server localhost:9092 \
  --create --if-not-exists \
  --topic analysis.jobs \
  --partitions 1 \
  --replication-factor 1
```

Проверить состояние сервисов можно командой `docker-compose ps`. Локальные
программы подключаются к Kafka через `localhost:9092`, а контейнеры API и worker
будут использовать внутренний адрес `kafka:19092`.

## Сборка серверной части

Worker собирается командой:

```bash
make worker
```

Для backend необходимы Drogon, `libpq`, `librdkafka`, `libsodium` и `pkg-config`:

```bash
brew install drogon libpq librdkafka libsodium pkg-config
```

После установки API собирается командой:

```bash
make backend
```

Сборка обоих компонентов:

```bash
make all
```

Посмотреть остальные команды Makefile:

```bash
make help
```

## Сборка десктопного клиента

React-интерфейс проверяется отдельно:

```bash
cd frontend
npm install
npm run lint
npm run build
```

Нативное приложение собирается через Tauri и Rust:

```bash
export PATH="$(brew --prefix rustup)/bin:$PATH"
npm run tauri build -- --debug
```
