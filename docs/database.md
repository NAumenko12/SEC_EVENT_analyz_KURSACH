# База данных

В каталоге находится реляционная схема Security Event Analyzer. Она описывает
пользователей, загрузки, задачи анализа, нормализованные события, правила
обнаружения, findings и отчёты. Справочные таблицы содержат типы источников,
статусы задач и уровни критичности.

Десктопный клиент не подключается к PostgreSQL напрямую. Он получает данные
через Drogon API, а уже API и worker работают с базой. Благодаря этому пароль от
базы не хранится внутри пользовательского приложения, а правила доступа и
проверки данных остаются в серверной части.

Backend подключается к PostgreSQL через официальную библиотеку `libpq`.
Параметры соединения передаются переменными `DATABASE_HOST`, `DATABASE_PORT`,
`DATABASE_NAME`, `DATABASE_USER` и `DATABASE_PASSWORD`. Локальные значения по
умолчанию совпадают с настройками PostgreSQL в `compose.yaml`.

`schema.sql` создаёт все таблицы, связи, ограничения и минимальный набор
стандартных правил. Он не запускается автоматически вместе с PostgreSQL. Это
сделано специально: запуск или перезапуск контейнера не должен незаметно менять
структуру базы.

До появления авторизации схема также создаёт неактивного технического
пользователя `local_desktop`. Он нужен только для соблюдения внешнего ключа
`uploads.fk_user_id` в локальной desktop-версии и не может использоваться для
входа.

## Применение к контейнерной базе

После запуска PostgreSQL схему можно применить вручную:

```bash
docker-compose exec -T postgres sh -c \
  'psql -v ON_ERROR_STOP=1 -U "$POSTGRES_USER" -d "$POSTGRES_DB"' \
  < database/schema.sql
```

Скрипт рассчитан на пустую базу. Перед применением изменений к рабочей базе
нужно сделать резервную копию и проверить SQL отдельно. После появления первой
серверной версии дальнейшие изменения схемы будут оформляться отдельными
контролируемыми обновлениями, а не перезаписью уже развёрнутой базы.
