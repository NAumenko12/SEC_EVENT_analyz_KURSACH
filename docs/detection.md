# Правила обнаружения

После нормализации событий worker читает из PostgreSQL активные правила для
типа источника. Порог, временное окно, критичность и рекомендация хранятся в
`detection_rules`, поэтому для их изменения не требуется пересобирать C++ код.

## SSH brute force

Правило `SSH_BRUTE_FORCE` рассматривает события `failed_ssh_login` и
`invalid_user_login`, у которых известен IP-адрес источника. События группируются
по IP и сортируются по времени. Скользящее окно ищет максимальное количество
попыток за `time_window_seconds`.

Если количество достигло `threshold_value`, создаётся один finding для этого
адреса. В текущей схеме по умолчанию используются 10 попыток за 120 секунд.
Finding получает критичность и рекомендацию из правила, а таблица
`finding_events` связывает его со всеми событиями найденного окна.

События, findings, связи, итоговые счётчики и статус задания сохраняются в одной
транзакции. При ошибке ни частичного анализа, ни finding без событий в базе не
останется.

Модульные проверки парсера и detection engine запускаются одной командой:

```bash
make test-worker
```
