# Текущее состояние проекта

## Что решили

Security Event Analyzer остаётся клиент-серверной mini-SIEM. Пользователь
работает в десктопном клиенте на React и Tauri. Клиент обращается по HTTP к C++
API на Drogon. PostgreSQL хранит данные, Kafka передаёт задания, а отдельный C++
worker выполняет анализ файлов.

## Что уже работает

- создана реляционная схема PostgreSQL из 22 таблиц;
- подготовлены PostgreSQL и Kafka в `compose.yaml`;
- C++ API и worker собираются через Make;
- работают `GET /api/health` и `GET /api/source-types`;
- backend подключается к PostgreSQL через `libpq`;
- ошибка подключения к базе возвращается как `503 Service Unavailable`;
- локальная база `sec_event_anal` создана на порту `5432`, схема применена;
- создан React + Tauri клиент;
- первый экран получает и показывает типы источников из Drogon API;
- настроены состояния загрузки, ошибки и повторного запроса;
- реализован `POST /api/uploads`;
- API проверяет размер, расширение и сигнатуру содержимого файла;
- файл сохраняется под UUID-именем и получает SHA-256;
- `uploads` и `analysis_jobs` создаются атомарно;
- API публикует задание в Kafka topic `analysis.jobs`;
- C++ worker получает сообщение и защищён от повторной обработки задания;
- worker обновляет статусы `queued`, `processing`, `completed` и `failed`;
- переходы сохраняются в `job_status_history`;
- работает `GET /api/jobs/{id}`;
- desktop-клиент отправляет файл и автоматически обновляет прогресс задания;
- реализованы регистрация, вход, проверка сессии и выход;
- пароли хешируются Argon2id, а в базе хранится только SHA-256 токена;
- загрузки сохраняются в каталоге пользователя и привязываются к его записи;
- API не позволяет получить задание другого пользователя;
- desktop-клиент получил экраны входа и регистрации;
- worker распознаёт SSH-входы и команды `sudo` из Linux `auth.log`;
- нормализованные события атомарно сохраняются в таблице `events`;
- клиент показывает количество обработанных строк и созданных событий;
- `DetectionEngine` применяет параметры активных правил из PostgreSQL;
- правило `SSH_BRUTE_FORCE` использует скользящее временное окно;
- finding связывается со всеми событиями, которые подтвердили атаку;
- клиент показывает количество созданных findings.

## Что проверено

- `make all` завершается успешно;
- health-check возвращает `200 OK`;
- справочник возвращает четыре типа источников;
- неподдерживаемый `POST /api/source-types` возвращает `405`;
- при недоступной базе endpoint возвращает `503`, а API продолжает работать;
- `npm run lint` и `npm run build` завершаются успешно;
- `cargo check` завершается успешно;
- Tauri собирает macOS-приложение размером около 30 МБ;
- интерфейс отображает четыре реальные записи из PostgreSQL;
- корректная загрузка возвращает `201 Created` и задание `queued`;
- неверное расширение и отсутствующий тип возвращают `400 Bad Request`;
- Kafka доставила тестовое задание worker;
- worker обработал две строки тестового журнала и установил `completed`;
- API вернул `progress: 100` и `processedRecords: 2`;
- история содержит переходы `queued → processing → completed`;
- проверены регистрация, вход, неправильный пароль и отзыв токена;
- строка, похожая на SQL-инъекцию, обработана как обычный логин и получила `401`;
- владелец тестового задания получил `200`, второй пользователь — `404`, а
  запрос без токена — `401`;
- модульный тест проверяет четыре поддерживаемых варианта строк `auth.log`;
- интеграционный файл из пяти строк создал четыре события, а неизвестная строка
  была безопасно пропущена;
- проверены IPv4, IPv6, исходный порт, пользователь, hostname и номер строки;
- модульный тест detection engine отсекает события вне окна и другой IP;
- интеграционный журнал создал 11 событий и один finding;
- finding высокой критичности связан с 10 неудачными SSH-входами.

## Важные детали

Homebrew-сборка Drogon не содержит PostgreSQL ORM, поэтому соединение реализовано
через официальную библиотеку `libpq`. Kafka producer и consumer используют
`librdkafka`. Интеграционная проверка выполнена с локальным PostgreSQL на порту
`5432` и Kafka из `compose.yaml` на порту `9092`. Настройки по умолчанию
по-прежнему рассчитаны на PostgreSQL из `compose.yaml` на порту `5433`.
