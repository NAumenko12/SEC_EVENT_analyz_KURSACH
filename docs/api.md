# HTTP API

API реализовано на C++ с помощью Drogon и по умолчанию доступно по адресу
`http://127.0.0.1:8080/api`.

## Проверка состояния

`GET /api/health` возвращает имя сервиса и состояние API.

## Типы источников

`GET /api/source-types` читает из PostgreSQL список поддерживаемых источников.
Desktop-клиент использует его для построения карточек выбора.

## Загрузка файла

`POST /api/uploads` принимает `multipart/form-data` с двумя полями:

- `source_type` — код из справочника `source_types`;
- `file` — один журнал или сетевой дамп размером до 20 МБ.

API проверяет расширение и базовую сигнатуру содержимого, заменяет исходное имя
случайным UUID, вычисляет SHA-256 и сохраняет файл в `data/uploads`. После этого
одна SQL-команда создаёт строки в `uploads` и `analysis_jobs`.

Успешный ответ имеет статус `201 Created`:

```json
{
  "uploadId": 12,
  "jobId": 8,
  "status": "queued"
}
```

Некорректный файл возвращает `400 Bad Request`. Внутренняя ошибка хранения или
базы возвращает `500 Internal Server Error` без раскрытия деталей клиенту.

Пока авторизация не реализована, локальные загрузки принадлежат неактивному
техническому пользователю `local_desktop`. Вход под этой записью невозможен.
После появления аутентификации API будет брать пользователя из проверенной
сессии, а техническая привязка будет удалена.
