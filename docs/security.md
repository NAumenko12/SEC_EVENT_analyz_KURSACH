# Безопасность

Текущая версия закладывает базовый безопасный контур многопользовательского
приложения. Защита выполняется на API, а не только в интерфейсе: desktop-клиенту
нельзя доверять, потому что HTTP-запрос можно отправить и без него.

## Учётные записи и сессии

- пароль имеет длину от 15 до 128 символов и никогда не хранится открытым;
- `libsodium` вычисляет Argon2id-хеш с собственной солью;
- при неверном логине и пароле API возвращает одинаковое сообщение;
- токен содержит 32 случайных байта и действует семь дней;
- в PostgreSQL хранится SHA-256 токена, а не сам bearer-токен;
- выход устанавливает `revoked_at`, после чего токен больше не принимается;
- неактивная или удалённая учётная запись не может использовать существующую
  сессию.

## Доступ к данным

Загрузка создаётся с `fk_user_id` из проверенной сессии. При чтении задания API
одновременно фильтрует его по идентификатору задания и владельцу. Поэтому знание
чужого числового идентификатора не даёт доступ к данным: API отвечает `404`.

Все значения регистрации, входа, сессий, загрузок и заданий передаются в
PostgreSQL параметризованными запросами `PQexecParams`. Пользовательский текст
не становится частью SQL-команды.

## Загружаемые файлы

API принимает один файл размером не более 20 МБ, проверяет допустимое расширение
и базовую сигнатуру содержимого. Исходное имя очищается до имени файла, а на
диске используется UUID внутри каталога пользователя. Для файла вычисляется
SHA-256. Интерфейс React выводит текст обычными компонентами и не вставляет его
как HTML.

CSV-экспорт пока отсутствует. При его появлении значения, начинающиеся с `=`,
`+`, `-` или `@`, нужно нейтрализовать перед открытием в табличном редакторе.

## Что ещё потребуется перед публичным сервером

- HTTPS и безопасное хранение токена средствами ОС;
- ограничение частоты входов и регистраций;
- регулярное удаление истёкших сессий;
- отдельные секреты и минимальные права PostgreSQL для API и worker;
- журналирование действий без паролей, токенов и содержимого приватных файлов;
- проверка зависимостей и резервное копирование.
